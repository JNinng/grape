# data

存储基础设施集合：一能力一子目录，目录内自包含（装配、实现、声明资产、生成产物）。能力目录实现 `biz` 声明的仓储接口，DO ↔ PO 转换、驱动错误映射在仓储内完成；接入规范见 [internal/README.md](../README.md) 的「能力目录接入规范」。

## 现有能力

- [pg_sqlc](pg_sqlc/)：关系存储（PostgreSQL，pgx/v5）。根包是存储门面与关系仓储（`Data` / `IdentityTx` 等会话门面、用户/部门/用户组/角色/菜单/字典/配置族（全局 + 租户）/会话/授权/审计日志/Agent 审计/检索留痕仓储、默认嵌入空间解析器、诊断面与维护面），另有查询 schema 出口注册表（[pg_sqlc/query_schema.go](pg_sqlc/query_schema.go)：`biz.QuerySchemaProvider` 契约的实现，资源名→生成代码 schema 出口的映射，确定性纯函数不触库，仅收录已暴露动态 List 的资源），声明资产在 [pg_sqlc/sqlc](pg_sqlc/sqlc/)（schema 按业务域拆分于 `sqlc/schema/`，另有 role/rls/operate/expose、Agent 域声明文件 96_agent_grant.sql 与 agent_session.sql/agent_vector.sql、菜单受控写面 98_menu_write.sql、全局配置受控写面 98_config_write.sql、租户删除前置受控计数面 98_tenant_guard.sql、queries/seed 与 sqlc.yaml），生成产物在 `pg_sqlc/gen/`（禁止手改，单 catalog 不随子包拆分）；SQL 对象索引、权限模型与生成命令见 [sqlc/README.md](pg_sqlc/sqlc/README.md)。两个子包只依赖根包、根包不反向引用：
  - [pg_sqlc/deploy](pg_sqlc/deploy/)：声明资产的部署面（执行清单 `DeployFiles`、口令占位符替换、跨进程部署锁、清单校验），dbdeploy 命令与各包 PG 集成测试共用，不依赖运行期门面。
  - [pg_sqlc/vector](pg_sqlc/vector/)：向量存储设施（biz.VectorStore 契约的 pgvector 介质，[vector_repo.go](pg_sqlc/vector/vector_repo.go)）：DDL 是超级用户面 [pg_sqlc/sqlc/agent_vector.sql](pg_sqlc/sqlc/agent_vector.sql)（不进 sqlc catalog，存取 SQL 手写参数化），一表承载多嵌入空间——embedding 列为裸 vector（维度随行），embedder/embed_dim 列逐行声明身份并由 CHECK 与实际向量长度绑定，检索以空间键等值 + 维度谓词命中对应维度的表达式部分 HNSW 索引；租户隔离由应用层强制（每条 SQL 带租户过滤、缺认证身份拒绝，读写经根包 IdentityTx），装配期探针校验部署表为多空间形状且每个 conf 声明维度存在匹配索引（缺索引启动即失败）。向量仓储经检索留痕装饰器（[retrieval_log.go](pg_sqlc/vector/retrieval_log.go)）包装后对外供给：Search 记 query/embedder/top_k/命中（来源 tool）、Add/Update/DeleteByFilter 记摄取侧（来源 pipeline），留痕失败只记日志不中断检索，检索内容与过滤摘要落库前经 pkg/redact 脱敏（wire 组合：`NewVectorStoreSupply` → `NewLoggedVectorStore` → 框架适配器与摄取管线；本子包的 ProviderSet 由 data 与根包集合并列聚合）。

  Agent 业务审计仓储在 [pg_sqlc/audit_repo.go](pg_sqlc/audit_repo.go)（biz.AuditRepo 契约的 PostgreSQL 实现）：两表 append-only + 租户 RLS（DDL 见 [pg_sqlc/sqlc/schema/95_agent_audit.sql](pg_sqlc/sqlc/schema/95_agent_audit.sql)，命名查询见 queries/agent_audit.sql），写入/查询经 IdentityTx，读侧 WHERE 带同源租户谓词兜底。检索留痕仓储在 [pg_sqlc/retrieval_repo.go](pg_sqlc/retrieval_repo.go)（biz.RetrievalLogRepo 契约的 PostgreSQL 实现，供 vector 子包的装饰器写入）：单表 append-only + 租户 RLS（DDL 见 [pg_sqlc/sqlc/schema/97_agent_retrieval_log.sql](pg_sqlc/sqlc/schema/97_agent_retrieval_log.sql)，命名查询见 queries/agent_retrieval_log.sql），写入/查询经 IdentityTx，读侧 WHERE 带同源租户谓词兜底。默认嵌入空间解析器在 [pg_sqlc/config_repo.go](pg_sqlc/config_repo.go)（biz.EmbedderResolver 契约的实现，该表的首个 Go 消费方）：读 sys_tenant_config 的 `vector.embedder` 键（IdentityTx，RLS 与显式租户参数双重声明），解析顺序「租户配置 > 全局 conf 兜底」，租户值指向未声明空间按 `ErrEmbedderUnknown` 严格拒绝（不静默回落），无缓存（唯一索引点读，每次摄取/检索现场解析）。

  配置族仓储在 [pg_sqlc/config_manage.go](pg_sqlc/config_manage.go)（biz.ConfigRepo / biz.TenantConfigRepo / biz.FeatureFlagRepo / biz.TranslationRepo 契约的 PostgreSQL 实现）：全局配置 sys_config 为平台级表（无 tenant_id、无 RLS），读走普通固定读与动态 List，写经受控写函数 fn_config_create/update/delete（[pg_sqlc/sqlc/98_config_write.sql](pg_sqlc/sqlc/98_config_write.sql)，super 命名；role.sql 对运行角色的直写 REVOKE 不动），写路径的平台信任边界（仅根租户可写）由 biz 用例经 [pg_sqlc/tenant_admin.go](pg_sqlc/tenant_admin.go) 的 NewPlatformTenantGuard 判定；租户配置 sys_tenant_config、功能开关 sys_feature_flag 与通用翻译 sys_translation 为租户表，读走 RLS + 动态 List，写为普通 DML（tenant_id 一律取会话 app.tenant_id）；功能开关按 `<tenant_id, flag_key>`、翻译按 `<table_name,row_id,column_name,locale,tenant_id>` 部分唯一索引限定未删除行间，软删后键/身份复用。与 config_repo.go 的嵌入空间解析器读路径并存：本仓储只补管理面，不改写既有消费路径（集成测试覆盖「管理写 → 解析器读到新值」的兼容性）。

  租户仓储在 [pg_sqlc/tenant_admin.go](pg_sqlc/tenant_admin.go)（biz.TenantRepo 契约的 PostgreSQL 实现）：sys_tenant 按租户树模型由 RLS 承担边界（策略允许 `tenant_id = app.tenant_id` 或 `id = app.tenant_id`），每个租户管理自己名下的直接子租户与自身，树外行天然不可见（等同不存在）；创建时 parent_id 只允许省略或等于调用方租户（结构父级与行归属一致），插入前同事务锁定调用方（父级）行，不存在/已软删返回 INVALID_ARGUMENT。方法名带 super 表达租户实体管理，不表示绕过 RLS，写路径是普通 DML（唯一例外是删除前置的只读计数函数）。id 由 `newTenantID` 发号（`t-` + 14 位小写十六进制，共 16 字符，crypto/rand，碰撞由主键约束兜底），tenant_id 一律取会话 app.tenant_id；删除先锁行并经 fn_tenant_active_child_count（SECURITY DEFINER，只返回计数、目标须对调用方可见）统计未删除直接子租户（有子拒绝，同事务；祖父看不到的孙行也计入，避免孤儿），停用/恢复为目标状态写；更新自身租户的 status（与当前值不同）被拒绝。同文件实现 biz.PlatformTenantGuard（NewPlatformTenantGuard）：在调用方租户事务内读自身租户行（RLS 放行 `id = app.tenant_id`），`parent_id IS NULL` 即平台根租户；租户不存在/已软删返回 false（fail-closed），供全局配置写路径的平台信任边界使用。
- [openaiembedder](openaiembedder/)：文本向量化设施（biz.Embedder 契约的 OpenAI 兼容端点实现，[openaiembedder.go](openaiembedder/openaiembedder.go)）：POST `{base_url}/embeddings`，多空间注册表经 conf.VectorSpaces 单一解析源构建（键 = model 或 model@version，键→端点/维度随空间持有；与 LLM provider 同口径，密钥经 ${ENV:...} 占位注入）；`vector.enabled=false` 返回禁用占位（调用按设施缺失拒绝），未知空间键按 `ErrEmbedderUnknown` 拒绝（不静默换空间）；每次 Embed 响应按所属空间声明维度复核，端点漂移调用点显式报错（维度链路三道校验：embedder 响应复核 / 摄取管线写路径逐次对账 / 部署探针多空间形状与每维度索引）。


## 诊断面

能力目录可另挂「诊断面」：实现 [biz/maintenance.go](../biz/maintenance.go) 声明的 `FacilityDiagnostics`，输出本设施的**原始**压力指标（不做比率与判定，阈值归监控配置层），经 data 的 `NewFacilityDiagnostics` 聚合、ops 的指标出口统一输出到 `/metrics`（server 直挂）；维护契约 `FacilityMaintenance` 按同一接缝消费。postgres 同时实现诊断面（[pg_sqlc/diagnostics.go](pg_sqlc/diagnostics.go)）与维护面（[pg_sqlc/session_repo.go](pg_sqlc/session_repo.go)）；缓存等新设施按同一模式接入（实现 + 追加进聚合点，不新增出口）。
